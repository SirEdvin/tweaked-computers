# Limit disposition and settings inventory

Planning baseline: commit `69e27d9`. This table covers the audit's categories, not a claim that implementation has already removed them. Implementation must attach every actual enforcement site to one row and fail its policy audit on an unclassified guard. Native finite/safe-integer domains, array shape, color encoding, prototype validity, permission and identity are not resource ceilings.

## Disposition

| Audit area | Disposition |
|---|---|
| Five execution/compilation/allocation/host/maintenance settings | Keep names; exhaustion becomes resumable work admission, not fatal poisoning |
| World registry, active computers/ledger participants, subscribed logic devices, subscription/output totals, shell sessions, monitor tiles | Remove fixed counts; account actual retained metadata and schedule fairly |
| Source/generated bytes, tokens/nodes, handlers, identifier lengths, tuple/local/constructor counts | Remove independent mod ceilings; aggregate compiler/runtime storage plus real native grammar/domain constraints; incremental compilation |
| Per-string/table/node/argument/result limits and default Data-copy ceiling | Remove duplicate shape limits; validate Data shape and charge aggregate ownership/lifetime; retain necessary configurable recursive-host depth only where iterative processing does not eliminate it |
| Computer state bytes/keys and labels | Retain aggregate storage protection, remove key/label/count ceilings; accepted contents survive lower settings |
| Queues, pending commands, timers/subscriptions | Configurable queued-work/retained-byte admission; event queues additionally retain configurable entry capacity; no fixed timer/subscription count; drop newest only for event deliveries |
| Console logs, cache, drafts, diagnostics | Configurable disposable retention; remove fixed draft/source/binding/search/session counts and field-length cuts that hide useful diagnostics; draft storage is protected non-disposable data |
| Logic input/filter/output and identity-name lengths | Remove count/name gates; native domains, aggregate memory and necessary engine output constraints remain |

| Advertised unused capacities and latency numbers | Remove misleading numeric promises; derive actual effective settings and measured workload claims separately |

## Setting families

All runtime resource settings are runtime-global and localized. Keys below are proposed stable names; existing keys must not be renamed. New aggregate defaults are provisional tuning values, to be verified against the declared gates before release rather than claimed as measured limits. Limits use integer accounting units unless noted, not measured Lua heap bytes or milliseconds.

| Setting | Scope / default basis | Exhaustion |
|---|---|---|
| `tc-compile-work` | Per computer per tick; preserve 1,250,000 default | Defer compilation cursor |
| `tc-callback-work` | Per computer per tick, shared program/Console; preserve 500,000 | Suspend current lane |
| `tc-callback-allocations` | Allocation throughput per computer/tick; preserve 81,920 | Defer allocation preparation; not a retained-memory substitute |
| `tc-host-work-per-tick` | World host/guest aggregate; preserve 5,000,000 | Fair deferral |
| `tc-maintenance-work-per-tick` | World maintenance share; preserve 200,000 | Fair deferral with reserved cleanup/control opportunity |
| `tc-runtime-memory-bytes` | Per computer live heap/frames/temporaries; proposed 8,388,608 | Atomic recoverable growth refusal |
| `tc-host-memory-bytes` | Shared retained host data including device metadata, models, pending proof/job state and snapshot/native-object accounting; proposed 134,217,728 | Growth refusal; retain accepted state |
| `tc-state-bytes` | Per computer application state; preserve 65,536 initially | Atomic recoverable write refusal |
| `tc-shell-value-bytes` | Per computer committed scratch graph; preserve 16,384 initially | Refuse candidate commit, keep old graph |
| `tc-draft-storage-bytes` | Per player retained editor/command drafts; proposed 1,048,576 | Refuse new growth visibly; preserve accepted drafts |
| `tc-event-queue-entries` | Per computer; preserve 128 initially | Drop newest incoming delivery |
| `tc-event-queue-bytes` | Per computer; preserve 65,536 initially | Drop newest incoming delivery |
| `tc-pending-work-bytes` | Per computer queued non-event work; proposed 1,048,576; also charged to host memory | Defer accepted jobs; reject new admission visibly |
| `tc-host-stack-depth` | Necessary remaining recursive host helpers only; default derived from the narrowest proven safe path, never less than supported existing input depth | Recoverable refusal before recursion; remove the setting if no protected recursion remains |
| `tc-console-entries` | Per computer disposable history; preserve 64 initially | Evict oldest, show truncation |
| `tc-console-bytes` | Per computer disposable history; preserve 16,384 initially | Evict oldest; one unfit entry refuses recoverably, no silent partial print |
| `tc-compiler-cache-bytes` | Host disposable compilation plans/proofs; proposed 8,388,608 | Evict; no semantic effect |
| `tc-render-commit-work` | Whole indivisible frame/group visibility publication; preserve 160,000 initially, within host allowance | Defer if transient; explicit blockage if impossible under full effective allowance |
| `tc-event-drop-warning-interval` | Per computer warning interval in simulation ticks; proposed 600 | Suppress duplicate warnings, never suppress counters |
| `tc-speaker-sound-page-size` | Discovery page retention, default 50 | Continuation pages, not catalogue refusal |
| `tc-monitor-width-tiles`, `tc-monitor-height-tiles` | Default/max 6, minimum 1 | Apply to new/reconciled geometry; grandfather existing content on setting-only decreases |

Per-owner host-memory subaccount usage is diagnostic; it is not another unadvertised capacity. Any other necessary retained-memory compartment identified during implementation must reuse these aggregate owners unless a distinct resource lifetime makes that unsafe; adding a new independent policy needs explicit justification and a setting, not a magic constant.

| Setting | Existing default | Meaning |
|---|---:|---|
| `tc-kv-keys` | 128 | Live keys per database |
| `tc-kv-bytes` | 16,384 | Live key/content bytes per database |
| `tc-kv-key-bytes` | 256 | Key/hash-field name bytes |
| `tc-kv-value-bytes` | 8,192 | String/field value bytes |
| `tc-kv-hash-fields` | 128 | Fields per hash |
| `tc-kv-hash-bytes` | 8,192 | Bytes per hash |
| `tc-kv-total-hash-fields` | 256 | Live hash fields per database |
| `tc-kv-command-arguments` | 128 | Arguments per command |
| `tc-kv-command-bytes` | 65,536 | Combined command input bytes |
| `tc-kv-snapshot-bytes` | 65,536 | New admission/transfer reservation including metadata |

KV count/byte/snapshot limits remain hard but recoverable. Settings combinations cannot permit a successful mutation that later loses data during mining; effective capacity and metadata headroom are calculated and shown before commit. Already accepted data is grandfathered for reads, cleanup and transport even after decreases. KV expiry/reclamation uses shared maintenance work instead of fixed eight-key/two-database throughput gates.

## Settings validation and interpretation

Use positive finite, exactly representable values within the actual Factorio setting/prototype domains. No zero-means-unlimited escape for safety budgets. Reject invalid settings or explain deterministic derived effective constraints; do not silently raise a requested budget. Freeze the tick ledger, not the settings UI: increases grant only remaining configured capacity, decreases do not renew credits or reinterpret valid retained state as corruption. Diagnostic/control/cleanup reservations are derived and reported from configured host budgets, not extra hidden maxima.

Storage/queue decreases do not evict accepted non-disposable work. Memory-releasing operations and status remain possible while over limit. A structural format/identity/native-domain validation is not made configurable merely to avoid labeling it a limit.
