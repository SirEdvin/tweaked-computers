# monitor-display resource-policy Lua API amendment

Proposed normative amendment to the existing [API](../../../../specs/monitor-display/lua-api.md), with unchanged details retained there unless explicitly replaced below. Shared execution, status and errors: [api-contract.md](../../api-contract.md).

Existing terminal methods, Color/Colour aliases, argument/result arities, byte glyph rules and 16-color hexadecimal blit encoding remain. Physical logical rectangles remain at most 6×6, with axis settings defaulting to six and never permitting more. The former 0.5..5 half-step scale gate is replaced by positive finite scale plus representable native geometry and configured resource admission; previous scales remain accepted. A geometry/scale mutation validates full model and presentation capacity before publishing or clearing cells.

`write`, `blit`, model storage and renderer staging have no unrelated fixed string/cell/frame ceiling. Resources are accounted by actual grid and lifetime. Accepted operations remain sequential from the caller perspective; callbacks may suspend but no half-prepared mutation is published. Completed model writes are visible to later reads/writers; automatic presentation waits for unfinished touching invocations to complete/terminate, not merely for a budget slice to end.

`peripheral.setMonitorSyncGroup(members [, group_key])` returns zero values. `peripheral.getMonitorSyncGroup([group_key])` returns one existing status shape plus applicable resource diagnostic. Omitted/nil key selects the legacy default group; an explicit nonempty string identifies another group within the current program-run or shell principal. Empty members clear only that key. No group/member/reference count cap applies. A display remains in at most one group because overlapping presentation barriers conflict. Replacement, canonical deduplication, red-before-green binding and ownership checks remain atomic. Stop/reset cancels all groups owned by that execution principal.

`getLimits()` retains effective width/height and actual native domains, adds policy version 2 resources and removes fixed aggregate/group/frame caps and unsupported latency promises. A ready indivisible commit too large for the configured allowance remains visibly blocked with setting guidance and its old fronts intact; it never partially publishes.
