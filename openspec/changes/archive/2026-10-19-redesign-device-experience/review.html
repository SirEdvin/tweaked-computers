Save is not Run

Validate checks the draft without effects. Save commits your source but leaves the current program alone. Run or Apply activates the saved revision.

Stop retains source, state and peripheral data. Reset State is a separate, confirmed operation in Maintenance.

Topic/search navigation and selectable examples. No undocumented API, new shell or filesystem.

Maintenance

Review source revisions and retained drafts without mixing recovery controls into everyday editing.

Review before Rebase or Reload. Copying recovery text changes only the draft; it never saves or runs automatically.

Reset computer state

Requires a stopped computer and a separate confirmation. KV data is not cleared.

Behavior that must survive the redesign

Dirty drafts, exact revision conflicts, standalone recovery, strict player/session authority, separate Save/Run, bounded logs and safe confirmations. The source widget stays mounted during tab, focus and status changes. A native implementation must be checked at different GUI scales; this browser mock is not evidence of Factorio layout or typing behavior.

One family. Five different machines.

Weathered steel, graphite panels, copper/brass terminals and restrained activity lights. Shape—not a letter or recolor—communicates function. These are schematic silhouette concepts, not final game sprites or exact socket coordinates.

Why “NETWORK” appears

The current visible body is a power entity without a circuit connector. An invisible selectable combinator owns the socket and has higher hover priority. That implementation detail leaked into play.

Proposed correction

The visible device owns its network endpoint; its power carrier becomes private. Multi-role devices use clearly integrated, named sockets. Red/green and Input/Output/Targets isolation remain intact.

The missing red X

Monitor drawing can cover native overlays. Verify the actual body receives the order, then keep display content below native feedback. Mark/cancel must not erase the screen or reset its identity.

The monitor cause is a source-supported hypothesis, not a client reproduction. The task explicitly checks both target ownership and rendering. Your native red X—not a custom replacement—is the acceptance criterion.
