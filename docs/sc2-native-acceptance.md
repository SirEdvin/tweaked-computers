## Production repair

Native R/Shift-R did not rotate deliberately inoperable shells: real player input
produced “Not operable” while headless writable-property assertions passed.
Hidden controls linked to the player's native rotate/reverse-rotate bindings now
forward only an owned, reachable, current-layout body with the correct force,
surface, permission, empty cursor and no GUI context. The synchronous native
`rotate` call temporarily permits operation and restores the closed shell even
on errors; the genuine native event reaches existing lifecycle handling exactly
once. No native combinator UI, synthetic duplicate lifecycle event, new budget,
backend or frame API is introduced.

Native engine behavior is quarter-turn for square shells and half-turn for the
nonsquare combinator shells. The retained first all-quarter-turn fixture
expectation was incorrect. The final guarded contracts and native campaign use
actual native semantics, preserve wires/ownership, and exercise R then Shift-R
on all five families in all four starting directions.

## Native matrix and interpretation

All client instances use private Xvfb displays and fresh isolated configs, mods,
write-data and saves. They never attach to the user's desktop or player data.
The actual renderer is **OpenGL llvmpipe software rendering**. Final passing cases
have normal native-window close or acknowledged server `/quit`, zero exits and
no forced cleanup; completion markers and exact counts are checked, not inferred
from startup or an encoded MP4 alone.

- Layouts: base, all four resolution/scale combinations. At 1280×720/100%,
  the first draft-reopen assertion expected Ctrl+Home to insert at document
  start, but native input inserted on the second line. The failed expectation,
  exact resulting draft and corrected retention/Save/Apply/Stop checks remain
  retained; no production change was made to force that test expectation.
- Physical lifecycle and maximum carried KV: base and Space Age, each with a
  fresh and separate cold full-client process; 57 final assertions per mode.
- Factory multiplayer: base and Space Age, each fresh client 1, actual late
  client 2, then a new server and two clients loading the frozen saved state.
  Fourteen fresh assertions per mode plus explicit ordinary-cold identity,
  no-replay, revision and world/ledger equality checks.
- Monitor multiplayer: base and Space Age, each a localhost server plus two
  real clients before and after ordinary cold load. Exact selected sequence,
  tick, models/palettes, owner state and snapshots agree on server and clients.
  A Space Age cold retry is retained separately from the interrupted original
  attempt; its four cold checks do not overwrite the fresh phase's provenance
  or get presented as the whole campaign's assertion count.
- Dense rendering: base and Space Age, each four cardinal 6×6 walls and the
  mixed 1×1/3×6/6×3/6×6 cohort, plus an independent scale-0.5 maximum display.
  All four 720-step fixtures reach their strict five-wall completion marker.
- Fixed-geometry appearance: base four-wall and Space Age mixed, scale 1 cohort
  plus independent scale-0.5 maximum; seven completed source frames each,
  two 25-second 750-frame recordings, contrasting native mark/cancel checks.
  Only test source/config differs; production payload bytes are verified equal.
- Current smooth chart: base and Space Age, exact shipped
  `examples/smooth-sine-chart.lua`, four selected cardinal screens, 600 measured
  ticks/300 complete changing publications per mode, maximum publication gap
  two simulation ticks. The two 8-second recordings and fixed-tick native
  screenshots were inspected. This supplements rather than replaces the
  existing mixed-layout/cold chart contracts.
- Native target GUI: both modes load a copy of the final factory-peer snapshot
  into another isolated full client and open the real inserter with mouse input.
  The visible Enable/disable checkbox and A > 0 condition agree with native
  readback. The earlier file named `lifecycle-base/configurator-view.png` was
  inspected and rejected: it showed terrain, not a target GUI. The first new
  capture's automatic GUI scale also targeted the wrong HUD button; its failed
  assertion and screenshot remain retained. The final captures explicitly set
  and read 100% scale rather than treating filenames as acceptance evidence.

Scale/geometry invalidation intentionally clears/hides the old geometry; native
power loss hides output without erasing cells. Those are explicit exceptions to
old-front retention. The videos show their blank intervals, native power-warning
overlays and individual restoration of valid old fronts before the next coherent
group publication. Initial preparation is also not a previously displayed image.
None is described as a no-blank guarantee across power/resize. Unrelated maximum
and selected-cohort screens do not have a cross-group publication barrier.

The all-frame colour audit excludes native red-wire crossings from its interior
regions; its first overinclusive false-positive report is retained. It samples
colour and up to eight horizontal bands, not every possible pixel defect, and is
used with native screenshots/transition-frame inspection and structural native
visibility assertions. Recorder frames are samples of actual windows, not
simulation-tick or screen-refresh guarantees.

## Limits and downstream handoff

The recorded smooth-chart diagnostics are approximately 40.14 UPS (base) and
40.87 UPS (Space Age), with whole-scheduler means approximately 22.67/22.12 ms
and p95 approximately 46.72/48.55 ms. They include observation/recording and the
software renderer; timed cases ran serially, but these are not uncontended,
matched-baseline, no-recording performance measurements. Neither the 30 FPS
recording nor two-tick publications establish hardware FPS or smooth real-time
60 UPS. Preserve these unfavorable observations for SC3 rather than raising
budgets, relaxing the 256-tick target, or freezing a supported envelope here.

Full admitted-world stress, matched CPU/latency and input-to-visible performance
remain **SC3** (`native` 7.1 / `buffer` 6.2), unchecked. Cross-project final
consolidation/PR is SC4; SC2 does not merge, publish, bump versions, alter
protection, edit generated OpenWiki, reopen command history or archive changes.
