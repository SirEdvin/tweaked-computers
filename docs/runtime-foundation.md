# TC01 native foundation: implementation contract

## Scope and verification policy

Tasks 1.1–1.3 implement the loadable mod, parser-only import, native literal
handler compiler, closed sandbox and one packaged headless smoke. Task 2.2
remains the full-language completion/review gate; state, activation, timers,
events and persistence orchestration belong to TC03. There are no gameplay
entities at this checkpoint.

The user requested complete specification implementation with lean checks:
reuse this harness, batch focused contract cases and run affected checks only.
No exhaustive fuzz/benchmark campaigns or graphical/client matrices here.
Client verification is deferred to the user until every specification is
implemented, not waived and not a blocker for this implementation card.
Published ceilings are provisional development bounds, not a release promise
of client latency or aggregate real-time CPU behavior.

## Entrypoints (trusted implementation code only)

Import modules during control.lua parsing. Never require inside an event.

    local admission = require('scripts.runtime.admission')
    local compiler = require('scripts.runtime.compiler')
    local ledger = admission.new()
    local context = admission.context(ledger, 'computer:1', game.tick)
    local plan, diagnostic = compiler.compile(source, context)
    local ok, diagnostic = compiler.run(plan, 'start', event, services, context)

compile returns a plain plan with compiler_version, api_version, exact source,
generated text, handler-name map and node count; it does not execute candidate
source. Failed candidates return nil and an ApiError-style diagnostic; the
caller must retain its prior active source/run. run constructs a new closed
environment and native descriptor every time. It returns true, or false plus
code/message/line/column. Its synchronous callback does not suspend and cannot
be restarted after failure. E_STOP is private host-facing control, not a guest
ApiError. Source line probes identify the current original statement/operator;
a complete precise traceback/source-map review remains task 2.2.

Plan data may be retained, but never retain functions or a guard/environment.
Source is revalidated on every run; caller-owned generated text is never trusted.
This intentionally cache-free foundation pays identical compilation/reconstruction
costs for fresh, retained and partially exhausted peers. An optimization must
preserve that admission behavior; there is no cache-performance claim here.

## Shared budget and service boundary

admission.new returns plain {version,tick,total,machines}. Persist one ledger
under the versioned storage root. context(ledger,id,tick) rejects backwards
clocks and retains each identity's spent work/compile/allocation counts for the
same tick. Only actual tick advance resets the ledger. Never delete a machine
counter on stop/removal/readmission. reserve(context,kind,amount) checks both
per-machine and aggregate ceilings before changing either counter. Warm/cold
run admission is identical: all dispatches revalidate the exact source and pay
generated bytes/nodes before their fresh native load.

services is a trusted table with computer/peripheral method maps. Wrappers
check fatal poison before touching host effects, validate and copy Data inputs
and outputs, preserve nil arity, and never expose a Factorio object. Service
implementations must validate arity/domain, recheck current authority and
reserve their own input-dependent native work before effect publication; the
compiler cannot authorize a network path for them. Earlier accepted effects
remain committed when a later call faults. Host teardown is independently
owned and must not call a guest cleanup handler.

Runtime guards also expose namespace(entries,label), service(fn), snapshot(v),
spend(n), check(), diagnostic(e) to trusted implementation modules. namespace
builds an opaque read-only guest table backed by ephemeral private entries.
For peripheral wrappers, supply a protected handle built with this same run's
guard: no raw host function/table/LuaObject return may cross service(). A method
captured from such a wrapper must revalidate authority on every call. These
are internal hooks, not guest exports. A service map or a guard-aware trusted
factory function(guard) -> service map can be passed to compiler.run. Build
peripheral handles with guard.namespace and guard.service in that factory;
never put those closures/proxies in storage.

Protected library tables are not copied Data, not mutable by table helpers and
not enumerable. Ordinary tables, including events/service readbacks, are fresh
plain values. API Data rejects cycles, metatables, function/userdata/thread
values, mixed map/array keys, sparse arrays and nonfinite numbers.

## Compiler and sandbox safety

Only the literal api_version=1 / named-function handlers descriptor is accepted.
The pinned parser resolves lexical locals. Default-deny validation rejects
host/global writes, private names, _ENV/_G, dynamic loading, colon calls,
labels/goto and unknown AST nodes. Every indexed read is rewritten through a
guard that rejects strings, so computed string keys cannot reach the native
string metatable. Native arithmetic/control flow/closures remain native Lua;
there is no opcode dispatch, coroutine execution or saved stack.

Every statement/loop iteration, call, argument/result movement, table creation,
growth, string/operator/helper work and function depth is admitted. A private
fatal sentinel poisons the run. Guest pcall checks poison and rethrows rather
than returning it; every later service boundary checks again. Native sort
comparators use the same call guard; mutation publishes after staging/admission.
Formatting/repetition/find/concatenation use bounded conservative byte estimates.
Only the explicitly approved standard helpers are installed. Descriptions of
tables/functions never reveal host addresses. Compile work covers pinned
scanner/parser/lookup loops plus bounded AST traversal/emission. Input, token,
AST, nesting and generated-output ceilings bound opaque native load work.

## Minimal storage/module conventions

storage.tweaked_computers has schema_version, next_id, entities, computers,
devices and player_drafts. registry.initialize is initialization/configuration
only; registry.get is read access. TC03 completes authoritative identity/binding
and lifecycle methods. Consumers should not infer entity schema from this
bootstrap. Each owned capability adds a narrow module under scripts/services,
not a dynamic guest extension bus. Runtime limits/errors/admission are shared.
